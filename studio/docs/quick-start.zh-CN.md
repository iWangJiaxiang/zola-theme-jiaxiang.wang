# 第一次使用创作中心

[English](quick-start.en.md) · [完整文档](../README.md) · [配置与排错](setup.md)

创作中心是博客的管理后台。你在网页里写文章、上传图片、维护设置；内容仍保存在自己的站点目录或 Git 仓库。公开网站继续由 Zola 构建。

## 1. 准备站点

需要 Node.js 22.12 或更高版本、npm，以及已有的 Wonder Shine 站点。站点根目录应有 `config.toml`、`data.toml` 和 `content/`。后台不会自动创建主站，也不会用演示内容替换你的文章。

若主题通过 submodule 安装，先在主站根目录执行：

```sh
git submodule update --init --recursive
cd themes/zola-theme-jiaxiang.wang/studio
npm ci
npm run setup -- --lang zh-CN
```

主题文件夹名称不同，请调整 `cd` 路径；独立克隆主题仓库时直接进入其中的 `studio/`。

## 2. 跟随终端设置

1. **内容来源**：电脑上的站点选「本地站点」；想直接修改 GitHub、CNB 等仓库选「HTTPS Git」。本地模式写本地文件，Git 模式直接向选定分支提交。
2. **站点目录 / 仓库**：本地目录指向主站根目录，常见结构默认 `../../..`。Git 模式填写最终 HTTPS 克隆地址、已经存在的分支、Git 用户名与访问令牌；分支以你的仓库为准，不能盲用默认 `main`。
3. **后台地址**：本地通常保留 `http://localhost:5173`。
4. **管理员账号与密码**：这是后台自己的账号，与 Git 账号独立；密码至少 12 个字符，输入不回显。

设置完成后自动生成 `.env`、密码哈希和随机会话密钥。不会显示或保存明文密码。已有 `.env` 会保留，不会覆盖。Ctrl+C 可取消尚未完成的设置。

不要先复制 `.env.example` 再运行向导：向导只创建新配置。如果已经复制，请按 [手动配置说明](setup.md) 填写，不必删除已有配置重来。

## 3. 检查并启动

```sh
npm run doctor -- --lang zh-CN
# Git 模式可额外执行：只检查读取，不写文件或推送
npm run doctor -- --connect --lang zh-CN
npm run dev
```

`PASS` 表示该项检查通过，`WARN` 是仍需确认的事项，`FAIL` 需要修复后再试。Git 可读取不等于具备推送权限；OIDC、云存储和网站发布仍需在实际环境验证。

打开配置的后台地址，用刚设置的账号登录。配置 `localhost` 时就用 `localhost`，不要换成 `127.0.0.1`。开发服务仅供本机访问；线上部署见 [EdgeOne 部署指南](deploy-edgeone.zh-CN.md)。

## 4. 在后台完成第一次创作

工作台会显示入门指引，可收起，之后从左侧「使用指南」重新打开。

1. 在「站点信息」确认名称、简介和正式网址，然后保存。
2. 在「标签与分类」添加名称，文章编辑时直接选择。
3. 在「媒体库」上传图片，也可以在封面等字段点击「选择或上传」。上传立即保存到仓库；选图、保存表单是后续步骤。
4. 在「文章」新建文章，填写标题、选择标签与分类，先保存为草稿。准备公开时取消「草稿」，再次保存。
5. 本地模式运行主站的 Zola 预览/构建流程；Git 模式到主站 CI 检查部署结果。

**保存成功不等于上线。**「已发布」表示文章不再是草稿，读者看到最新内容还需要一次成功的网站部署。后台不会自动创建 CI，也不会显示未经验证的部署成功。

## 5. 常用操作

- 页面正文在「页面」编辑；进入页面后的「页面设置」维护模板专属配置。两者分别保存。
- 友链使用「本地图标」选图、上传和预览；「备用图标地址」保留原始地址，后台不自动拉取。
- 默认英文，首次按浏览器偏好选中英文或中文；右上角随时切换，不改变文章或主站语言。
- 保存冲突时先下载备份，再重新读取、合并；备份是 JSON 恢复副本，不是可直接发布的 Markdown。
- 账号忘记、Git 权限、图片未上线等问题见 [配置与排错](setup.md)。
